<GuideSection id="module-1" index="M1" title="Flaw remediation foundations">

Classify system flaws, evaluate source credibility, and measure the window of exposure.

<GuideLab id="L1.1" title="Understanding system flaws" objective="Classify five findings and explain the risk and reporting requirement for each.">

1. Read `SI-M1-L1_Flaw_Examples.txt` and `ACS-POL-SI-002_Remediation_Timeline.txt`.
2. Open `SI-M1-L1_Worksheet.txt`.
3. For every finding, record its classification, risk level, risk explanation, and whether a remediation ticket is needed.
4. Use these categories:

| Category           | Examples in this lab                     |
| ------------------ | ---------------------------------------- |
| Software flaw      | Adobe Acrobat heap overflow              |
| Configuration flaw | SMBv1, unsigned LDAP, or TLS 1.0 enabled |
| Patching gap       | Failed cumulative update                 |

5. Save at least 100 characters of reasoned analysis as `{{siArtifactsPath}}SI-M1-L1_Completed.txt`.

</GuideLab>

<GuideLab id="L1.2" title="Active vs passive flaw identification" objective="Decide which vulnerability sources are credible and actionable.">

1. Review `SI-M1-L2_CISA_Advisory.txt`, `SI-M1-L2_Vendor_Alert.txt`, and `SI-M1-L2_Blog_Post.txt`.
2. Compare publisher, CVE assignment, technical evidence, vendor confirmation, and available mitigation.
3. In `SI-M1-L2_Worksheet.txt`, classify each source and explain whether it should trigger remediation.
4. Treat the CISA advisory and Microsoft bulletin as trusted; the anonymous unsupported claim requires verification.
5. Save the completed analysis as `{{siArtifactsPath}}SI-M1-L2_Completed.txt` with at least 100 characters.

</GuideLab>

<GuideLab id="L1.3" title="Window of exposure" objective="Calculate whether eight findings meet the remediation timeline.">

1. Read `SI-M1-L3_Exposure_Data.csv`, `SI-M1-L3_Timeline_Reference.txt`, and `SI-M1-L3_Quick_Reference.txt`.
2. Apply the policy thresholds: Critical 7 days, High 14, Medium 30, Low 90.
3. For each finding, calculate discovery-to-remediation days, or discovery-to-today if it is still open.
4. Record compliance, the most critical gap, and two recommendations.

```powershell
$date = Get-Date -Format "yyyy-MM-dd"
$summary = @"
SI LAB M1-L3 - Window of Exposure Analysis
Pod: {{podName}} | Date: $date | Analyst: [Your Name]
For each SI-2026 finding record exposure days, policy maximum, and COMPLIANT or NON-COMPLIANT.
Total Findings: 8
Most Critical Gap: [Finding and reason]
Recommendations: [Your actions]
"@
Set-Content "{{siArtifactsPath}}SI-M1-L3_Completed.txt" $summary
```

</GuideLab>

</GuideSection>

<GuideSection id="module-2" index="M2" title="Vulnerability assessment and patch verification">

Read scanner output, distinguish attempted updates from successful remediation, and create formal findings.

<GuideLab id="L2.1" title="Read a vulnerability scan" objective="Determine which Nessus findings violate the remediation policy.">

1. Read `SI-M2-L1_Nessus_Scan.txt` and the remediation timeline policy.
2. Analyze all three findings:

| Finding                                   | Severity     | Age      | Policy maximum |
| ----------------------------------------- | ------------ | -------- | -------------- |
| CVE-2026-21001, SMBv1 RCE                 | Critical 9.3 | 365 days | 7 days         |
| Expired SSL certificate                   | High 7.4     | 47 days  | 14 days        |
| Missing speculative-execution mitigations | Medium 5.6   | 182 days | 30 days        |

3. State why all three are noncompliant, recommend an action for each, and identify the first priority.
4. Save the report as `{{siArtifactsPath}}SI-M2-L1_Completed.txt`.

</GuideLab>

<GuideLab id="L2.2" title="Patch verification" objective="Establish whether cumulative security updates actually installed.">

1. Read `SI-M2-L2_Patch_History.csv` and `SI-M2-L2_Event_Log.txt`.
2. Separate successful Defender definition updates from failed cumulative updates.
3. Note Event ID 20 installation failures, Event ID 19 successes, error `0x80070643`, and the repeated failure pattern.
4. Explain why a failed attempt leaves the vulnerability open, identify the root cause, and recommend corrective actions.
5. Save as `{{siArtifactsPath}}SI-M2-L2_Completed.txt`.

<GuideCallout title="Verification rule" tone="warning">

Patch activity is not proof of remediation. The cumulative update must install successfully and be confirmed by a rescan.

</GuideCallout>

</GuideLab>

<GuideLab id="L2.3" title="Remediation reporting" objective="Create the formal finding and remediation ticket for the critical SMBv1 vulnerability.">

1. Open `SI-M2-L3_Report_Form.txt` and `SI-M2-L3_Nessus_Reference.txt`.
2. Complete the report for `SI-2026-001`, CVE-2026-21001, CVSS 9.3, on `{{podPrefix}}-ACS-SRV-002`.
3. Record network exploitability, no required privileges or interaction, patch KB5035849, and a deadline seven days after discovery.
4. Route the Critical finding to the IT Administrator and CISO, with rescan as the verification method.
5. Save the exact report name `SI-M2-L3_Completed.txt`.
6. Complete `SI-M2-L3_Ticket_Template.txt` with the finding, host, due date, remediation steps, and rescan requirement; save as `SI-M2-L3_Remediation_Ticket.txt` with at least 50 characters.

</GuideLab>

</GuideSection>

<GuideSection id="module-3" index="M3" title="Malware protection status">

Audit endpoint coverage, scan cadence, and definition currency across the pod inventory.

<GuideLab id="L3.1" title="Verify AV installation and coverage" objective="Find endpoints without effective malware protection.">

1. Review `SI-M3-L1_AV_Inventory.csv`, `SI-M3-L1_Endpoint_Status.csv`, and policy sections 3.1-3.4.
2. Check product installation, real-time protection, definition date, last full scan, and compliance result.
3. Document these key gaps:
   - `{{podPrefix}}-DEV-Laptop-04` has no antivirus.
   - `{{podPrefix}}-Legacy_Server` has 2019 definitions and a stale scan.
   - The other four systems are compliant.
4. Record the total, compliance rate, issue, policy violation, risk, and recommendation for each failed endpoint.
5. Save as `{{siArtifactsPath}}SI-M3-L1_Completed.txt`.

</GuideLab>

<GuideLab id="L3.2" title="Review malware scan logs" objective="Verify that weekly scans complete across protected endpoints.">

1. Read `SI-M3-L2_Scan_History.csv` and `SI-M3-L2_Event_Log.txt`.
2. Use Event ID 1000 for scan start, 1001 for completion, and 2000 for definition updates.
3. Confirm weekly scans for `{{podPrefix}}-WS01` and `{{podPrefix}}-ACS-SRV-002`.
4. Mark `{{podPrefix}}-Legacy_Server` noncompliant because its last scan was in November 2025.
5. Mark `{{podPrefix}}-DEV-Laptop-04` noncompliant because no AV is installed.
6. Save the per-system cadence, result, event observations, and overall status as `{{siArtifactsPath}}SI-M3-L2_Completed.txt`.

</GuideLab>

<GuideLab id="L3.3" title="Definition currency" objective="Identify stale signatures and systems that policy requires you to isolate.">

1. Review `SI-M3-L3_Definition_Status.csv`, `SI-M3-L3_Coverage_Reference.csv`, and policy section 3.3.
2. A definition older than 7 days is noncompliant; older than 30 days requires isolation.
3. For all six endpoints, record version, update date, days since update, status, and action.
4. Isolate `{{podPrefix}}-Legacy_Server` until its 2019 definitions are updated and a full scan completes.
5. Require AV installation on `{{podPrefix}}-DEV-Laptop-04`.
6. Save as `{{siArtifactsPath}}SI-M3-L3_Completed.txt`.

</GuideLab>

</GuideSection>
